# Contributing to QuizApp

Thanks for improving the project. Keep changes focused, reproducible, and easy to review.

## Workflow
1. Create a focused branch for the change.
2. Reproduce the issue or define the expected behavior before editing.
3. Make the smallest coherent change that solves the problem.
4. Run the repository's available checks before committing.
5. Use a clear commit message describing the change.

## Quality expectations
- Do not commit secrets, local environment files, generated dependencies, or machine-specific artifacts.
- Keep unrelated refactors out of focused fixes.
- Update documentation when behavior or setup changes.
- Include useful reproduction details for bug fixes.

## Pull requests
Explain what changed, why it changed, and how it was verified. Note any known limitations or follow-up work.
